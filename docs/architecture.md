# Architecture decisions

## Processing kernel

Use C++20 and a cascade of up to twelve second-order IIR sections. Each section contributes two poles or fewer, requires bounded state and adds no lookahead or block delay. Its frequency-dependent phase is part of the response. Linear-phase FIR would introduce a latency/transition-width trade-off and possible pre-ringing. Oversampling adds cost and filtering without a nonlinear stage to justify it. The baseline uses double coefficients and double transposed-direct-form-II histories, including for future float host buffers. Configure one Cascade per channel with identical parameters. Preserve channel histories across host blocks. The initial configure method clears them and is for stopped audio only.

Each section uses the RBJ cookbook’s bilinear-transform design. Bell Q follows the cookbook convention, filters use second-order 12 dB/octave asymptotes, shelves use fixed slope S=1. Q acts on bell and cut filters. Gain acts on bell and shelves. Default cut Q is 1/√2. The graph multiplies the exact complex section responses at the active rate. This also yields a phase reference for tests. Never infer the response from a fitted UI spline. [Filter equations](https://www.w3.org/TR/audio-eq-cookbook/)

## Transition boundary

Before connecting a live knob, compare bounded control-rate redesign against a topology-preserving state-variable realization under automation. Keep the static core as an oracle. Trial a 10 ms time-based ramp on log Hz, log Q and dB. Maintain ramp phase across variable blocks; avoid redesign of unchanged sections. A type change or enable/bypass switch can change histories discontinuously. Trial a short complementary linear wet/dry or old/new crossfade, with preallocated state and bounded retargeting. Test repeated interrupts. Choose duration and implementation from transient measurements and listening. During transitions the graph shows the target and converges with settled audio. Host parameter gestures, playback, restore and smooth changes are essential. Sample-offset automation guarantees, internal envelopes, audio-rate modulation and dynamic EQ are outside the 1.0 contract.

## Host, formats and license

Use JUCE 8 with CMake at the host boundary. Its VST3/AU wrappers, parameter attachments and native graphics cover our two targets with one editor and one build description. iPlug2 is a viable lighter alternative with a permissive approach and its own graphics layer. Direct SDK integration would require separate format lifecycle, GUI embedding, parameter and validation work. JUCE reduces that initial integration surface. Keep JUCE types out of the kernel so the choice remains reversible. Pin a tested release by full commit at wrapper integration, inspect its bundled SDK revision and retain all required notices. JUCE offers AGPLv3 and commercial terms. The maintainer must establish the applicable distribution path before shipping; private repository visibility does not select a license. Steinberg’s MIT terms apply to SDK 3.8 onward. Check the actual copy distributed. ## Parameter and state contract for M2

The host owns one parameter model per instance. Allocate twelve permanent slots in fixed order. Each has enabled, shape, frequencyHz, gainDb and q. Add global bypass for 61 parameters. Proposed IDs are band.01.enabled through band.12.q and global.bypass. Freeze host numeric mappings, AU version hints, wrapper identity, enum indices and normalized ranges in a golden manifest before giving anyone a plugin build. Never recycle an ID or reorder choices. Reserve shape order bell, low shelf, high shelf, low pass, high pass. Persist requested physical values including currently inactive fields. Frequency 20–20000 Hz and Q 0.1–18 use log mappings, gain ±24 dB uses linear mapping. Clamp effective Hz to 0.45 times sample rate and show any clamp in the inspector. Sample-rate changes preserve the requested value. Default to dry, all slots disabled, global bypass off.

For host chunks and user presets, implement a versioned sound-state envelope, bounded parsing, validation into a temporary model and one coherent commit. Apply documented defaults to absent fields, ignore unknown optional fields, migrate older supported schemas and reject malformed or unsupported versions without disturbing current audio. Persistent sound state excludes filter histories, analyzer buffers and transient selection. Store editor preferences separately. Restore at prepare time or via a bounded handoff; avoid mixed old/new bands within a restore. The editor sends begin/change/end gestures through the host model. Automation refreshes both views from that model without echoing another gesture.

## Thread ownership

The processor owns all audio state for the instance. At a block boundary consume current targets; handle bulk restores coherently. Audio processing must never allocate, take locks, perform I/O, or invoke GUI code. Prepare all buffers outside the callback and scope denormal suppression around processing. The UI reads snapshots of values and active rate and computes its own curve. Overlapping hit tests need deterministic cycling or explicit slot selection. Analyzer copies go to a bounded single-producer/single-consumer queue. Drop visual frames if full. A worker windows and transforms channel data; combine channel powers to preserve antiphase stereo. Publish the latest complete frame to the UI. Editor closure stops analysis work and never changes audio. Keep analysis FFT latency separate from the host-reported audio latency.
